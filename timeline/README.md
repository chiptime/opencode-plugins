# opencode-time-footer

Append a machine-local time footer to each completed OpenCode text block. The label follows your system locale by default, with an English fallback. You can select a locale or supply a custom label; repeated completion of a block with an existing trailing footer does not duplicate it.

**Limitation:** this plugin uses `experimental.text.complete`. It marks a completed text block, **not a guaranteed full-turn boundary**. A footer may appear before further tool calls, and one turn may contain multiple timestamped text blocks. The experimental hook may change in future OpenCode versions.

## Installation

Requires an OpenCode build that supports the `experimental.text.complete` plugin hook. Add it to the `plugin` array in your `opencode.json` — the global config at `~/.config/opencode/opencode.json`, or a project-local one:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-time-footer"]
}
```

Version 0.2.0 follows the system locale instead of always defaulting to Spanish. To select a language regardless of system settings, pass a `locale` options tuple:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [["opencode-time-footer", { "locale": "es" }]]
}
```

To use your own text, pass `label` instead:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [["opencode-time-footer", { "label": "Finished at" }]]
}
```

Quit and restart OpenCode after changing plugin configuration; no live restart is required for development tests.

## Label and locale options

Labels resolve in this order: **label > locale > system (`LC_ALL` > `LC_MESSAGES` > `LANG`) > English**.

1. A nonblank string `label` wins and is used verbatim, including surrounding whitespace.
2. A nonblank string `locale` selects a built-in label. An unsupported explicit locale falls back to English without system detection.
3. With no explicit label or locale, the plugin checks `LC_ALL`, then `LC_MESSAGES`, then `LANG`, using the first supported language. Empty values, `C` (including `C.UTF-8`), `POSIX`, values without an alphabetic base language, and unsupported languages are skipped.
4. If nothing matches, the label is `Finished at` (English).

Non-string and blank option values are ignored. Locale normalization lowercases the value, takes the part before the first `_`, `-`, `.` or `@`, and keeps only letters `a`–`z`. For example, `ES`, `es-ES`, and `es_ES.UTF-8` select Spanish; `PT_br` selects Portuguese.

| Locale | Language | Footer label |
|--------|----------|--------------|
| `en` | English | `Finished at` |
| `es` | Spanish | `Finalizado a las` |
| `pt` | Portuguese | `Finalizado às` |
| `fr` | French | `Terminé à` |
| `de` | German | `Beendet um` |
| `it` | Italian | `Finito alle` |

The locale changes only the label, not the timestamp format or timezone.

## Output

With `"label": "Finished at"`, a completed text block looks like:

```text
The requested change is complete.

[Finished at 14:05:09]
```

The timestamp is computed when the hook runs using the machine's local clock (`Date.getHours()`, `getMinutes()`, and `getSeconds()`), with zero-padded `HH:MM:SS`. It is not generated by the model and does not measure elapsed time. Local timezone and daylight-saving settings apply.

Blank blocks are unchanged. A trailing footer with the resolved label is preserved, including its original timestamp and any trailing whitespace. The plugin does not write log files.

## Development

From the repository root, install workspace dependencies with `bun install`. Then, from `timeline/`, run:

```sh
bun test timeline.test.ts
bun run build
npm pack --dry-run
```

The build emits `dist/index.js` for Bun and keeps `@opencode-ai/plugin` external. The dependency is imported only for types, so the compiled plugin has no runtime import of it; its peer dependency is optional. The package also includes `index.ts` so the types export resolves. `prepublishOnly` runs the tests and build before publication.

Source stays at `timeline/index.ts` for existing local symlink installations. Tests use a controlled clock, save and restore all three locale environment variables per test, and cover local time, locale normalization and precedence, default and custom labels, and idempotency.
